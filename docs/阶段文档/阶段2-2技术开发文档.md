# 阶段 2-2 技术开发文档｜AI 能力矩阵

> 配套文档：`docs/PRD/PRD.md`、`docs/PRD/方案.md`、`docs/阶段文档/技术适配声明.md`、通用技术栈手册。
> 本文档只覆盖阶段 2-2。复用阶段 2-1 的状态机、repository、schemas 与统一错误处理。

## 一、阶段目标

- 交付范围：AI 能力矩阵（周报 / 诊断 / 摘要 / 起草 / 问答）+ 统一模型客户端（超时/重试）+ Prompt 独立文件 + 输出 Pydantic 校验 + 规则降级 + `scripts/smoke.py`。
- 验收标准：真实模型冒烟 5 条链路全过；A06 / A08 / A11–A14 行为与旧 Demo 一致。
- 明确不做：重启恢复钩子（阶段 2-3）、正式前端、上线。

## 二、技术适配摘要

- 采用：requests + 有限重试；Pydantic 校验模型输出；Prompt 独立文件。
- 偏离/暂缓：无独立 Agent 编排层（五项能力各自一个最小闭环：取数→调模型→校验→渲染/降级）。

## 三、技术栈与模型

- 模型：`gpt-6.2-astra`（OpenAI 兼容 `chat/completions`），服务端调用，密钥走 `.env`。
- 组件：`ai_client.py`（超时 + `MODEL_MAX_RETRIES` 次重试 + 用量采集）、`ai_services.py`（五能力）、`reporting.py`（规则取数与降级）。

## 四、环境与配置

- `MODEL_API_BASE` / `MODEL_NAME` / `MODEL_API_KEY` / `MODEL_TIMEOUT` / `MODEL_MAX_RETRIES`。

## 五、项目结构（本阶段新增）

- `app/services/ai_client.py`、`app/services/ai_services.py`、`app/services/reporting.py`
- `app/services/prompts/{report,diagnosis,summary,draft,qa}.md`
- `app/schemas/ai.py`（模型输出 Pydantic + 请求结构）
- `app/api/report.py`、`app/api/ai.py`
- `scripts/smoke.py`

## 六、数据与状态

- 周报草稿表 `report_drafts`（owner/scope/week_start 唯一）；数据截止时间随草稿保存。
- 历史周按「当期截止前的最后事件」还原节点与处理人，排除之后的操作。

## 七、API 设计

| 接口 | 方法 | 请求体 | 响应 |
| --- | --- | --- | --- |
| `/api/report?role=&scope=&week_start=` | GET | — | `{draft?, report?}` |
| `/api/report/generate` | POST | `ReportGenerateRequest` | 周报（completed/pending/next_week + method + data_cutoff） |
| `/api/report/save` | POST | `ReportSaveRequest` | `{ok}` |
| `/api/diagnose` | POST | `DiagnoseRequest` | `{risks[], method, data_cutoff}` |
| `/api/summary` | POST | `SummaryRequest` | `{summary, method}` |
| `/api/draft` | POST | `DraftRequest` | `{text, method}` |
| `/api/qa` | POST | `QaRequest` | `{answer, refs[], method}` |

## 八、Prompt 设计

五份 Prompt 独立文件；每份约定：只归纳输入事实、引用任务编号、只输出 JSON。程序负责分组/数量/状态标签与引用校验，模型只组织文字。

## 九、验收界面

复用 `static/` 临时验收界面，不新增。
