## 1. 项目判断

- 产品类型：银行支行「智能办公与协同管理平台」比赛 Demo（Web 端，本地运行）。
- 主要用户：支行内部四个模拟身份——综合岗（安排）、零售岗（经办）、运营岗（复核）、支行负责人（看板 + AI 支行范围）。
- 主要终端：桌面 Web 为主，兼顾移动 Web（390px 起）。
- 新项目或已有项目：已有项目。后端已验收通过；前端由阶段 2 的临时验收界面迁移为正式前端。
- 本阶段业务目标：把后端 MVP 换成正式前端（Next.js），废弃 `backend/static/`，跑通五条核心业务闭环。

## 3. 技术选择

- 框架与版本：Next.js 稳定版（App Router）+ React 稳定版 + Node.js 当前 Active LTS；版本以建项目时稳定版为准，锁定 `package-lock.json`。
- 样式与组件策略：Tailwind CSS + CSS 语义变量（`@theme`），Lucide 图标；对话框/下拉框等无障碍复杂组件用 shadcn/ui；不用 emoji 当功能图标。品牌基调：上海银行色调「蓝 + 银」（主色深蓝、辅色银灰，用于导航/强调/边框），D15 已定。
- 数据请求与状态策略：React 自带状态 + 集中式 API 客户端；不预装 TanStack Query / Zustand；URL 承载任务 ID / 筛选 / 页签；后端为最终事实来源。
- 流式通信策略：无流式 / WebSocket；活动窗口 3 秒轮询刷新（PRD 明确）。
- 表单方案：React Hook Form + Zod（安排任务、提交/退回说明等有校验）。
- 测试方案：Vitest + React Testing Library；一次性 Playwright 脚本做浏览器截图检查（非 E2E 套件）；lint / typecheck / test / build 为交付门槛。
- 部署环境：本地运行（D9 不上线）；`proxy.ts` 把 `/api/*` 请求时转发到 `process.env.BACKEND_URL`（本地 `http://127.0.0.1:8000`）。

## 4. Agent 状态

- 后端状态 → 前端统一状态映射：

| 后端状态（业务枚举） | 前端统一状态 | 用户看到什么 / 能做什么 |
| --- | --- | --- |
| 待办理 | idle | 尚未开始，经办人可「开始办理」 |
| 办理中 | running | 执行中，经办人可「更新」「提交复核」 |
| 待复核 | waiting_user | 等待复核人确认：「复核通过」或「退回补充」 |
| 待补充 | waiting_user | 等待经办人补充：「更新」后「重新提交」 |
| 已完成 | succeeded | 展示实际完成时间 |
| （逾期 / 临期） | stale 标记 | 程序按截止时间计算的附加标记，不等同于失败 |
| （周报草稿有新进展） | stale | 提示「有新进展，可重新生成」 |

- 等待用户确认方式：任务状态机由确定性代码 + 版本号校验约束；前端按当前处理人展示操作按钮；过期/重复操作后端返回 `conflict`（「任务已更新，请查看最新状态」），前端刷新详情，不做乐观覆盖。
- 取消、重试、断线恢复方式：无自主长任务；AI 生成（周报等）失败提供「重试」和「查看按规则汇总」；读取失败保留已有内容 + 重试入口；刷新后按 URL 里的 `task_id` 回查后端真实状态。
- 任务 ID 和恢复入口：任务详情路由 `/tasks/[id]`；工作台、看板、通知、周报引用均跳到同一详情，返回时保留原筛选。

## 5. 页面与产物

- 核心页面：

| 页面 | 路由（草案） | 说明 |
| --- | --- | --- |
| 我的工作台 | `/` | 今日 / 本周 / 我的待办 三视图 + 综合岗「安排任务」 |
| 任务详情 | `/tasks/[id]` | 状态动作 + 操作记录 + 退回意见 + AI 摘要 |
| 站内通知 | `/notifications` | 未读数 + 临期/逾期提醒，点击进详情 |
| 支行看板 | `/board` | 本周统计 + 指标筛选（仅负责人）+ 一键诊断 + 问进度 |
| AI 周报 | `/ai/report` | 个人/支行范围 + 报告周 + 可编辑草稿 + 引用点击跳转 |
| （AI 起草） | 上下文入口 | 安排任务时「AI 起草说明」、退回时「AI 起草退回意见」 |

- 核心业务闭环（5 条）：
  1. 安排 → 开始 → 更新 → 提交复核 → 复核通过（A01–A05）；
  2. 退回补充 → 更新 → 重新提交（A03 分支）；
  3. 看板指标筛选 → 进入任务详情 → 返回保留筛选（A04）；
  4. 通知未读 → 点开详情 → 已读（A05 旁路）；
  5. AI 周报 / 诊断 / 问答真实生成 + 规则降级（A06 / A08 / A11–A14）。

- 产物类型和预览方式：周报文本（可编辑草稿/保存/引用点击跳转）、诊断风险列表、问答回答 + 引用、摘要/起草文本；无图片/视频/音频。
- 响应式目标：390 / 768 / 1280 / 1440 四档；桌面侧栏在手机变抽屉或底部导航；表格改卡片。
- 阶段 3 子阶段规划（抄自《技术适配声明》第 7 节并按手册第 22 节细化）：

| 子阶段 | 做什么 | 产品经理验收时做什么 |

## 6. 偏离本手册的地方

| 偏离项 | 原因 | 影响 |
| --- | --- | --- |
| 鉴权方式：手册默认「邀请码换 Cookie 会话」，本项目用「右上角模拟身份切换」（角色经请求参数传给后端，无真实登录） | 比赛 Demo 定位；PRD 明确「角色切换仅用于模拟演示」，D5 已定 | 无真实用户隔离；权限判断仍在后端按 role 校验（前端隐藏按钮不算权限）。做成正式产品需重新评估 |

其余默认技术栈（Next.js App Router / TypeScript strict / Tailwind CSS / Vitest / shadcn/ui / React Hook Form + Zod / proxy.ts 同源转发）全采纳，无偏离。
