## 1. 本阶段目标

把后端 MVP 换成正式前端的第一步：搭起可运行骨架，做出一页「我的工作台」代表页，给产品经理确认视觉方向（上海银行色调「蓝 + 银」，D15）。

## 2. 范围

### 本阶段包含

- 页面：我的工作台（`/`），今日 / 本周 / 我的待办三视图。
- 组件：应用外壳（顶栏 + 侧栏 + 移动端抽屉）、身份切换、任务卡片、加载/空/失败状态。
- 接口：`GET /api/bootstrap`（身份列表）、`GET /api/tasks`（工作台）。
- 任务状态：后端业务状态 → 前端统一状态映射（idle / running / waiting_user / succeeded / stale / unknown）。
- 产物：设计变量（蓝 + 银 `@theme`）、`proxy.ts` 同源转发、Vitest + React Testing Library、lint / typecheck / build。
- 废弃：`backend/static/` 临时验收界面（停止对外提供入口，文件保留，见《前端适配声明》第 6 节）。

### 原工作台阶段后续范围

- 任务详情 / 看板 / 通知 / AI 周报页面（3-2、3-3）。
- 创建任务、状态动作（3-2）。
- AI 能力交互与 3 秒轮询（3-3）。
- 响应式全站打磨、无障碍全量检查、发布准备（3-4）。

## 3. 用户流程

1. 打开前端首页，默认以「零售岗」身份看到工作台（今日视图）。
2. 右上角切换模拟身份（综合岗 / 零售岗 / 运营岗 / 支行负责人），列表随之刷新。
3. 在「今日 / 本周 / 我的待办」三个视图间切换。
4. 手机打开：侧栏收起为抽屉，点左上角汉堡展开。

## 5. 接口契约

- `GET /api/bootstrap` → `{users, demo_time, model_available}`。
- `GET /api/tasks?role=&view=`（view ∈ today / week / todo）→ `{tasks: [...]}`。
- 错误统一 `{"error":{"code","message"}}`，前端归一化为 `ApiError`（含 `userMessage` 与 `retryable`）。
- 超时与重试：本阶段无流式；读取失败保留空态并给「重试」入口。
- Mock 与真实切换：本阶段直接对接阶段 2 已验收的真实后端，无 mock 数据。

## 6. 实现方案

- 路由：`app/layout.tsx`（根布局）→ `app/page.tsx`（工作台，客户端组件）。
- 组件结构：`components/app-shell.tsx`、`identity-switch.tsx`、`task-card.tsx`；`lib/`（roles、task-status、role-context、api/client、proxy/forward）。
- 状态来源：身份用 `useSyncExternalStore` 存 LocalStorage；视图用组件 state；服务端数据来自后端 API。
- 流式/轮询：无（3-3 引入 3 秒轮询）。
- 响应式处理：桌面固定侧栏 + 顶栏；<768px 侧栏变抽屉，无残留遮挡。
- 安全与隐私：身份切换只传 role 查询参数，权限由后端判定；`proxy.ts` 服务端转发 `/api/*` 到 `BACKEND_URL`，不暴露后端地址与密钥；前端无任何密钥。

## 8. 风险与回退

- 风险：身份切换无真实登录，同一浏览器多人共用会互相覆盖身份（Demo 定位，D5 已定）。
- 降级：后端不可用时前端显示错误 + 重试，不白屏；身份列表用内置兜底。
- 回退：删除 `frontend/` 即回到阶段 2 的临时验收界面（`static/` 文件仍在）。
- 改动影响：对最终用户无影响（本地 Demo）；对后续维护：后端仅提供 `/api/*`，前端成为唯一入口。
