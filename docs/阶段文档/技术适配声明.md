# 技术适配声明

> 配套：`docs/PRD/PRD.md`（V2）、`docs/PRD/方案.md`（V2）、`AI Agent 产品 Vibe Coding 通用技术栈手册` V2.4。
> 本文档在阶段 1 产出，作为后端 MVP（阶段 2）开工前的技术基线说明。

## 1. 产品形态判断

- 产品类型与核心任务：银行支行「智能办公与协同管理平台」比赛 Demo。核心是一条确定性任务状态机（安排→办理→提交复核→退回补充→通过），叠加看板统计、站内通知、到期提醒，以及 AI 能力矩阵（周报 / 诊断 / 摘要 / 起草 / 问答）。
- 核心交互：分阶段确认（任务流程由人一步步操作）+ 单次生成（周报等一次生成、可编辑保存、可重新生成）。Agent 部分无动态工具调用、无多轮自主执行。
- 开发路径：**后端先行**。阶段 2 已完成（2-1 骨架与状态机、2-2 AI 能力矩阵），后端整体验收通过；原生 HTML/JS 前端（`backend/static/`）在阶段 2 作为临时验收界面复用。2026-11-21 产品经理确认进入正式前端，D14 由「不做正式前端」变更为「做正式前端」。
- 验收界面：阶段 2 的 `backend/static/` 为**临时验收界面**（FastAPI 挂载），阶段 3 起整体废弃，改由 `frontend/`（Next.js）承接；是否表第 4、7 项自阶段 3-1 起生效。
- 上线套餐：不适用（**不上线**，本地 Demo）。对应决策台账 D9。
- 当前阶段范围：阶段 2（后端 MVP）已验收通过；现进入阶段 3（正式前端），子阶段规划见第 7 节。

## 2. 采用的默认方案

| 方案 | 采用原因 |
| --- | --- |
| Python 3.12 + FastAPI | 延续旧 skeleton 技术栈，符合默认基线，服务端可独立验证 |
| Pydantic | 校验接口输入、响应，以及模型结构化输出 |
| pytest | 第一层 mock 自动化测试（业务逻辑、状态流转、错误路径） |
| Git | 框架根目录初始化仓库；`verify.sh` 的密钥排除检查依赖它 |
| 模型调用（OpenAI 兼容接口） | 官方 `chat/completions` 接口，服务端调用，密钥走 `.env` |

## 3. 触发的按需模块

| 模块 | 触发需求 | 当前阶段是否引入 |
| --- | --- | --- |
| SQLite（裸，stdlib） | 多实体关系、事务、并发修改（任务/事件/通知/草稿/用户五张表） | 是，但用裸 SQLite + repository 抽象，不引 ORM |
| SSE | 需逐步展示模型内容 | 否（3 秒轮询已满足双窗口演示，PRD 明确不引 WebSocket/SSE） |
| Chroma / RAG | 知识库语义检索 | 否（比赛未要求 RAG，周报直接查任务记录） |
| 任务队列 | 长耗时任务 | 否（无跨请求长任务） |
| SQLAlchemy / Alembic | 关系型数据库管理 | 否（见第 4 节偏离说明） |

## 4. 偏离或暂缓的默认方案

| 默认方案 | 替代方案 | 原因 | 影响 | 何时重新评估 |
| --- | --- | --- | --- | --- |
| SQLAlchemy + Alembic | 裸 SQLite + repository 接口 | Demo 仅 6 任务、单机、无并发写入，ORM 属按需模块未触发 | 数据访问集中 repository 层，未来可替换实现 | 出现复杂筛选/并发/多实例时 |
| 真实登录 + 数据归属 owner_id | 模拟身份切换（右上角切角色） | 比赛 PRD 明确「角色切换仅用于模拟演示」，真实组织账号是后续接入项 | 无真实用户隔离 | 若做成正式产品再评估 |
| Next.js 正式前端 | 复用原生 HTML/JS 临时验收界面 | 阶段 2 只做后端；比赛交付物沿用已验证的前端 | 前端不重做、不进生产构建 | 阶段 3（2026-11-21 已确认进入，见《前端适配声明》） |
| 腾讯云上线部署 | 本地运行 | 比赛为本地 Demo，PRD 未要求上线 | 无线上资源 | 若需要对外试用再评估 |

## 5. 强制底线检查

- 密钥与隐私：**通过**。`.env` 进 `.gitignore`，密钥仅后端读取，不入前端、不入库、不入镜。
- 数据与任务可恢复：**通过**。SQLite 持久化；提供 `scripts/restart-check.sh` 由 `verify.sh` 实测重启恢复。
- 输入输出校验：**通过**。Pydantic 定义请求/响应结构；统一错误结构 `{"error":{"code","message"}}`。
- 错误与日志边界：**通过**。异常统一映射，不泄露堆栈；日志不记密钥与完整用户文档。
- 测试与真实模型验收：**计划** = 第一层 pytest（模型一律 mock）+ 第二层 `scripts/smoke.py` 真实冒烟并自动写 `冒烟记录.md`。
