## 1. 产品目标与成功条件

BranchRelay 让一项工作从安排、办理到复核始终有明确的接手人。员工在任务详情中提交一次，下一岗的待办、负责人的看板和生成周报所用的工作记录随之更新。

| 命题痛点 | 产品行为 | Demo 成功条件 |
|---|---|---|
| 任务交接后还得逐人通知 | 提交复核时转移责任人，同时生成待办通知 | 经办人操作一次，复核岗能从通知直接打开同一任务 |
| 负责人要逐人询问进度 | 看板显示当前节点、当前处理人、到期情况和最新记录 | 双窗口演示时，负责人无需刷新，在 5 秒内看到变更 |
| 每周重新拼凑工作记录 | 基于本周任务事件及截止时状态生成可编辑周报 | 每条业务结论能打开对应任务；待复核的工作不会被写成已完成 |

以上是验收目标。答辩可报告实测同步时间、操作次数和周报核对结果；节省工时需有对照测量后再引用。

## 2. 用户、权限与产品范围

| 演示角色 | 可见内容 | 可执行操作 |
|---|---|---|
| 综合岗（任务发起人） | 自己发起或参与的任务、个人周报 | 安排工作、填写经办人和复核人、查看流转记录 |
| 零售岗（示例经办人） | 自己参与的任务、个人待办和周报 | 开始办理、填写进展、提交复核、按退回意见补充 |
| 运营岗（示例复核人） | 自己参与的任务、个人待办和周报 | 查看提交说明、通过或退回 |
| 支行负责人 | 全支行演示任务及其记录、支行周报 | 查看进展、定位阻塞、生成并编辑支行周报 |

“经办人、复核人”按任务指定，岗位名是演示身份。一个人可在不同任务中担任不同职责，同一任务的经办人与复核人须不同。发起人和负责人可以查看进展，节点操作只对该节点的当前处理人开放。首页右上角提供模拟身份切换，每个浏览器标签页保留自己的身份，便于两个窗口同时演示。

**首版必做**：今日与本周安排、任务创建与办理、复核和退回、站内交接及到期提醒、负责人看板、官方模型生成周报、数据持久化。

**有余量再做**：周报复制、按岗位筛选、任务时间线展开细节。真实组织账号、外部消息推送、多级审批和制度问答留作后续接入。比赛未要求 RAG，本版周报直接查询任务记录，无须建立知识库。

## 3. 主场景与任务状态

周一，综合岗发起“金融知识宣传活动初稿准备”，指定零售岗编写、运营岗复核。周五上午，零售岗提交初稿并注明“请核对活动时间”。运营岗收到提醒。负责人查看该任务，发现初稿已提交、复核仍待办理，可以直接找到下一位处理人。运营岗通过后，任务才计入已完成；如果活动时间有误，可退回并附上修改意见。

| 操作 | 前置状态 | 谁操作 | 新状态 / 当前处理人 | 同时发生 |
|---|---|---|---|---|
| 创建 | 新建表单有效 | 综合岗 | 待办理 / 指定经办人 | 生成编号、创建记录，通知经办人 |
| 开始办理 | 待办理 | 经办人 | 办理中 / 经办人 | 记录开始时间 |
| 更新进展 | 办理中或待补充 | 经办人 | 状态和处理人不变 | 追加文字进展，更新看板最近动态 |
| 提交复核 | 办理中或待补充 | 经办人 | 待复核 / 复核人 | 保存提交说明、记录交接，通知复核人 |
| 退回补充 | 待复核 | 复核人 | 待补充 / 原经办人 | 必填退回原因，通知经办人 |
| 复核通过 | 待复核 | 复核人 | 已完成 / 无待办人 | 记录完成时间，通知发起人与经办人并去重 |

待补充任务可直接重新提交。完成后的任务只读。**逾期是时间标记**，可以和“待复核”等状态同时出现。示例中的“初稿准备”是一项任务，复核通过只代表初稿任务完成，不能据此宣布整场宣传活动结束。

## 4. 页面与交互需求

### 4.1 我的工作台：明确今天要处理什么

- 默认打开“今日”。优先显示自己当前负责且已经逾期的任务，再列今日到期的任务；“本周”显示自己参与、且计划日、截止日或流转记录落在本周的任务。另设“我的待办”入口，显示全部未结待办，覆盖未来到期事项。
- 每行显示标题、编号、截止时间、节点、当前处理人及下一步操作。“待复核 · 今日到期”可并列显示，避免只靠颜色区分。
- 综合岗可点“安排任务”。表单包含任务标题、工作说明、计划日、截止时间、经办人、复核人。标题、两个岗位、计划日和截止时间必填；截止日早于计划日、两岗位为同一人时，在字段旁提示。成功后打开新任务，接手人看到新待办。
- 无任务显示“今日没有到期或逾期的待办”，提供“查看本周”。读取失败保留已有内容和更新时间，显示重试入口。

### 4.2 任务详情：完成一次有记录的交接

- 顶部显示任务目标、状态、截止时间和当前处理人；下方显示发起人、经办人、复核人及按时间排列的操作记录。退回意见在当前经办人的操作区可见。
- “提交复核”包含一条必填的交付说明，例如“宣传文案初稿已整理，请核对活动时间”。回车或点击提交后显示“已交给运营岗复核”。“退回补充”必填原因；“复核通过”后显示实际完成时间。
- 操作提交中禁用按钮。状态、处理人、事件、通知在同一次事务中写入。若另一窗口已完成该操作，提示“任务已更新，请查看最新状态”，重新加载详情，避免重复交接。
- 工作台、看板、通知和周报引用均打开同一任务详情。返回列表时保留原筛选。

### 4.3 站内通知与重要日期提醒

- 站内消息显示未读数、时间、任务标题和需要执行的动作。点击后标记已读并进入详情。已读只影响消息标记，待办保持到办理完成或转交。
- 当前处理人的未完成任务在截止前 24 小时内触发临期提醒；超过截止时刻触发逾期提醒。打开应用和列表轮询时检查即可，无需为本地演示配置后台定时服务。
- 同一任务、接收人、截止时间和提醒类型只产生一条日期提醒。交接消息按流转事件去重。已完成任务停止产生到期提醒。活动筹备等重要日期以任务截止时间进入今日 / 本周安排。

### 4.4 支行看板：找到需要跟进的那件事

- 默认展示本周任务，统计口径与工作台“本周”一致，范围扩展为全支行。顶部显示本周任务数、当前已完成数、待复核数、当前逾期数。逾期与节点数量允许重叠。
- 点击指标筛选下方列表。例如点“待复核”，能看到任务、当前复核人、最近提交说明及等待起始时间。点击任务查看历史，返回后筛选仍在。
- 双窗口共用服务端数据。建议每 3 秒刷新活动窗口数据，操作发起窗口成功后立即更新。若读取失败，保留最后更新时间，恢复后自动重试。

### 4.5 AI 周报：从任务事实生成草稿

- 入口提供“个人 / 支行”范围和报告周选择。个人范围仅含本人参与的任务；支行范围仅对负责人开放。生成后显示统计截止时间，可编辑草稿、保存并再次打开。已有编辑时，重新生成前提示将替换该草稿。
- 默认按北京时间周一 00:00 至下周一 00:00（不含）取数。本周未结束时以演示当前时刻为截止。历史报告按当期截止前的最后事件还原节点和处理人，排除之后的操作。
- “本周完成”只收录本期复核通过的任务。“待推进”列出本周相关且截止时仍未完成的任务，按逾期、待补充、待复核优先。“下周安排”来自已登记的下周计划日或截止日。无记录时显示“暂无已登记安排”。
- 程序计算数量和状态，模型仅接收所选角色可见的任务编号、标题、节点、处理人、期限和本期文字记录。要求每一项引用已有编号，不推测延误原因、完成比例或客户成效。引用在页面上可点击。
- 生成中显示进度提示；重复点击只发起一次请求。模型超时、密钥缺失、返回格式异常或引用未知编号时，保留原草稿，提供“重试”和“查看按规则汇总”。规则汇总明确标注来源。所选范围无记录时直接给出空态。
- 草稿保存生成时的数据截止时间。源任务随后变化时提示“有新进展，可重新生成”，保留人工编辑版本直至用户确认替换。

**给模型的最小输出约定**

```json
{
  "completed": [],
  "pending": [
    {"task_id": "T-003", "text": "宣传初稿已提交，待运营岗核对活动时间。"}
  ],
  "next_week": []
}
```

渲染前校验每个编号属于本次输入，且所属分组与程序判定一致。页面中的数字、当前责任人和状态标签直接取自数据记录。模型只负责归纳文字。

## 5. 数据与实现约定

建议用一个本地 Web 服务、SQLite 和浏览器实现。VS Code 用于开发，官方模型 API 由服务端调用。实际接口地址、模型名、鉴权方式依官方提供的信息配置；密钥放在环境变量中。演示数据初始化与模型调用相互独立。

| 数据对象 | 最小字段 | 用途 |
|---|---|---|
| 用户 | 用户编号、显示名、岗位、角色 | 模拟身份和可见范围 |
| 任务 | 任务编号、标题、说明、发起人、经办人、复核人、当前处理人、计划日、截止时间、当前状态、版本号、创建 / 更新 / 完成时间 | 工作台和看板共用；版本号用于检测重复或过期操作 |
| 流转记录 | 事件编号、任务编号、操作者、动作、前后状态、操作后的处理人、说明、时间 | 追踪交接、还原历史、形成周报依据 |
| 通知 | 通知编号、接收人、任务编号、类型、去重键、消息、创建 / 已读时间 | 交接通知与时限提醒 |
| 周报草稿 | 草稿编号、归属人、范围、周起始日、数据截止时间、引用编号、内容、生成方式、最后编辑时间 | 保存、回查及区分模型草稿与规则汇总 |

服务端承担查询与角色范围校验，写入前验证当前处理人、状态和版本。创建任务时一并写入首条事件。本版任务的计划日、截止时间和角色在创建后固定，以便周报可重现。角色切换仅用于模拟演示。

## 7. 验收清单

| 编号 | 操作 | 通过条件 |
|---|---|---|
| A01 任务安排 | 综合岗创建一项合法任务，再试一次相同经办人和复核人 | 首次创建后经办人获得待办，非法组合提示修改 |
| A02 跨岗交接 | 重置数据；零售岗提交 T-003；另一窗口保持负责人看板打开 | 原经办人待办移除，运营岗收到可点击的交接消息；5 秒内看板待复核由 1 变 2 |
| A03 退回再提交 | 运营岗退回 T-003，零售岗补充后再次提交，运营岗通过 | 意见可见，历史顺序正确，最终已完成且不再有当前处理人 |
| A04 日期与通知 | 重置后反复打开工作台，查看 T-003、T-004 并点击提醒 | 前者临期，后者逾期；每种到期提醒只出现一次，已读不清除待办 |
| A05 越权与重复操作 | 经办人尝试复核；两个复核窗口对同一版本连续点通过 | 拒绝不合法操作；只生成一条有效通过记录，统计只增加一次 |
| A06 周报准确性 | T-003 提交、尚未通过时生成支行周报 | 本周完成仅含 T-001、T-002；T-003 在待推进，T-006 在下周安排；引用能回跳，无虚构延误原因 |
| A07 周报编辑与持久化 | 修改并保存周报、刷新，再重启本地服务 | 保存的文字、任务状态、事件和已读状态仍在 |
| A08 API 失败 | 在模型不可用时生成周报 | 页面给出重试及带标签的规则汇总，原草稿保留，任务仍可办理 |
| A09 范围与历史 | 以零售岗打开周报，再选择一个无任务的更早周 | 只能读取参与任务；空周不调用模型，当期完成数为零 |
| A10 历史截止 | 在测试数据中为同一任务补入次周通过事件，再查看上周周报 | 上周按当时的待复核状态呈现，次周通过不会计入上周已完成 |

## 8. 实施顺序与答辩视频

| 顺序 | 开发内容 | 完成判断 |
|---|---|---|
| 1 | 初始化模拟数据和四个角色；用虚构任务试通官方 API | 可稳定重置到初始快照，知道模型接口能否正常调用 |
| 2 | 先完成创建、开始、提交、退回、通过以及流转记录 | 同一条任务能完整走通，刷新后进度保留 |
| 3 | 接工作台、通知和看板 | 从一个窗口提交任务，另一个窗口能看到真实更新 |
| 4 | 接周报取数、模型调用、引用、草稿保存与失败处理 | 通过 A06–A10，能解释每条周报的依据 |
| 5 | 录屏、导出、复查运行方式 | 建议 11 月 22 日 11:00 前完成视频导出，留出一小时检查并提交 |

**建议录制约 3 分钟**，具体时长以主办方要求为准。

1. **0:00–0:20**　打开负责人看板，指出本周 5 项任务和那条已经逾期的补充事项，说明负责人可以直接找到处理人。
2. **0:20–1:15**　切到零售岗，从“今日”打开 T-003，填写“初稿已整理，请核对活动时间”并提交。并排展示负责人看板上的待复核数变化。
3. **1:15–1:50**　切到运营岗，点开新通知，展示交接人、提交时间和说明，暂时保留待复核状态。
4. **1:50–2:40**　用负责人身份生成支行周报，展示“已提交，待复核”的表述，点击 T-003 核对来源，再展示下周已登记的分享会。
5. **2:40–3:00**　运营岗点击通过，看板已完成数从 2 变为 3。展示完整时间线，以同一条任务从安排到完成的记录收尾。

提交前从干净的初始数据启动一次，确认录屏文字可读、模型密钥未入镜，且实际交付的启动说明足以让评委复现这条流程。

## 3. 功能需求

- **FR1 任务安排（V1）**：综合岗创建任务，字段含标题、说明、计划日、截止时间、经办人、复核人；标题/两岗位/计划日/截止时间必填，截止早于计划日、经办人=复核人时字段旁提示；成功后生成编号、写入首条事件、通知经办人并打开新任务。
- **FR2 任务办理（V1）**：经办人可开始办理（记录开始时间）、更新进展（追加文字）、提交复核（必填交付说明）。
- **FR3 复核流转（V1）**：复核人可复核通过（记录完成时间、通知发起人与经办人并去重）或退回补充（必填原因、通知经办人）；完成后任务只读，待补充可直接重新提交。
- **FR4 我的工作台（V1）**：今日/本周/我的待办三个视图；今日逾期优先再列今日到期；本周按计划日/截止日/流转记录落本周取数；无任务显示空态，读取失败保留旧内容并提供重试。
- **FR5 任务详情与流转记录（V1）**：展示目标、状态、截止、当前处理人、发起/经办/复核角色及按时间排列的操作记录；提交中禁用按钮；版本冲突时提示「任务已更新」并重载；返回列表保留原筛选。
- **FR6 站内通知与到期提醒（V1）**：未读数、时间、任务标题与动作；点击标记已读并进详情；截止前 24h 内触发临期、超时触发逾期；同一任务+接收人+截止+类型只生成一条；已完成停止提醒。
- **FR7 支行看板（V1）**：默认本周，统计本周任务数/已完成/待复核/逾期（允许重叠）；点击指标筛选列表并展示复核人、最近提交说明与等待起始时间；活动窗口 3 秒轮询、操作窗口成功后立即更新，失败保留最后更新时间并自动重试。
- **FR8 AI 周报（V1）**：个人/支行范围与报告周选择；按北京周一 00:00 至下周一（不含）取数，未结束周以演示当前时刻截止；历史按当期截止前最后事件还原；输出「本周完成/待推进/下周安排」三组、引用可回跳；草稿可编辑保存；模型失败时保留原草稿并提供重试与带标签的规则汇总；空范围不调用模型。
- **FR9 数据持久化（V1）**：SQLite 存用户/任务/流转记录/通知/周报草稿；提供一次性初始化或重置命令回到固定快照；刷新与重启后数据仍在。
- **FR10 角色与权限（V1）**：服务端承担查询与角色范围校验，写入前验证当前处理人、状态与版本；拒绝越权（如经办人复核）与重复（如双窗口重复通过）操作。
- **FR11 AI 进度诊断与风险预警（V2 新增）**：负责人视角对全支行本周任务做分析，识别逾期、待复核积压、待补充卡点与阻塞点，输出受影响任务及跟进建议；引用任务编号，不虚构延误原因。
- **FR12 AI 任务摘要（V2 新增）**：把单条任务的流转记录归纳成一句话进展摘要，显示在工作台列表与任务详情；摘要随最新事件更新。
- **FR13 AI 智能起草（V2 新增）**：综合岗起草任务说明、复核人起草退回意见时，AI 按岗位语气润色或补全，用户可编辑后再提交；不自动落库。
- **FR14 AI 自然语言看板问答（V2 新增）**：负责人用自然语言查询进度（如「这周谁逾期最多」「哪些任务卡在复核」），服务端转为查询并归纳回答，遵守角色范围并带任务引用。
- **FR15 AI 输出统一约束（V2 新增）**：所有 AI 输出必须引用已有任务编号、不得虚构延误原因/完成比例/客户成效；数量、责任人与状态标签由程序计算；模型不可用时各能力走规则汇总或空态降级；生成方式与数据截止时间随草稿/结论记录。

## 4. 边界与红线

- 数据全部为虚构，页面标注「比赛模拟数据」，不使用客户材料或银行内部制度。
- 不接入真实组织账号、外部消息推送、多级审批、制度问答与 RAG 知识库。
- 官方模型 API 密钥只放服务端环境变量，不入库、不入镜、不写进报告或聊天。
- 所有 AI 输出（周报/诊断/摘要/起草/问答）只归纳已有任务记录，必须引用已有任务编号，不推测延误原因、完成比例或客户成效；页面数字/责任人与状态一律取自数据记录。
- AI 查询与结果均遵守角色范围（个人仅本人参与任务，支行范围仅负责人），服务端二次校验。
- 同一任务的经办人与复核人不得为同一人；节点操作只对当前处理人开放。

## 5. 成功指标（可度量）

- A01–A10 验收清单全部通过（任务安排、跨岗交接、退回再提交、日期通知、越权重操作、周报准确性、持久化、API 失败、范围历史、历史截止）。
- A11 AI 诊断：负责人看板一键诊断，输出与「本周 1 项待复核、1 项逾期、2 项已完成」一致的风险点，且引用可回跳。
- A12 AI 摘要：T-003 提交后列表一句话摘要更新为「初稿已提交，待运营岗复核」。
- A13 AI 起草：起草框可生成并允许人工编辑，不自动写入流转记录。
- A14 AI 问答：问「这周谁逾期最多」返回 T-004 及经办人，且零售岗身份无法查询支行范围。
- 双窗口演示：负责人看板在操作后 5 秒内看到待复核/已完成数变化。
- 周报每条业务结论可回跳对应任务，待复核工作不写成已完成。
- 刷新与重启后任务状态、流转记录、通知已读与周报草稿仍保留。
